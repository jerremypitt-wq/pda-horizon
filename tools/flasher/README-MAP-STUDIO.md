# HorizonMapStudio 1.13.0 — карты, вкладки и геопривязка

**Прошивка ПДА: 1.12.0.ZI или новее (1.14.0 — без встроенной игровой карты).** На новом ПДА после установки прошивки сперва нужна смонтированная LittleFS: только для нового/полностью стёртого устройства запиши пустую файловую систему из ZIP прошивки опцией флешера «СТЕРЕТЬ данные». Затем загрузи проект через HorizonMapStudio. На уже используемом ПДА эту опцию не выбирай: она удалит чаты, настройки и карты; обычное обновление кода их сохранит. Старый `HorizonFlasher.exe` не меняется: в нём остаётся прежний редактор **одной** карты. Для проекта с этажами пользуйся только `HorizonMapStudio.exe`. Сборка в Windows: `tools\flasher\build_map_studio.bat`; готовый файл — `tools\flasher\dist\HorizonMapStudio.exe`. Для запуска из исходников: `python tools\flasher\map_studio.py` после установки `requirements.txt`. Готовый EXE не требует установки Python или ZIP прошивки.

1. Открой JPG 3:2 (480×320–960×640, ≤8 МиБ) или `.hzmap` старого/нового формата. Если рядом с JPG есть `pois.txt`, точки загрузятся с ним.
2. `+ JPG` создаёт новую вкладку с отдельной картой и точками; до **4 вкладок**, всего до **50 стартовых точек**. Выбирай вкладку в списке, добавляй/перетаскивай точки, переименовывай, удаляй, меняй порядок стрелками. «Открыть JPG» при открытом проекте **заменяет текущую карту вместе с её стартовыми точками** после подтверждения. Сохраняй проект `.hzmap` перед отправкой.
3. Чтобы отметить координаты карты, переключись в режим **«Геопривязка»**. Щёлкни по изображению в месте, для которого знаешь координаты, впиши название, широту и долготу **WGS84 в десятичных градусах** (например, `50.775345` и `6.083887`; юг и запад со знаком `-`), нажми «Сохранить привязку». В списке справа можно выбрать и поправить любую опору; зелёные пронумерованные ромбы существуют **только в редакторе**. X/Y — пиксели исходного JPG, их можно уточнить вручную. До **20 привязок на вкладку**; для будущей калибровки лучше выбрать хотя бы три далеко разнесённые точки, не лежащие на одной прямой. Это совет, не автоматическая проверка точности. Сохрани `.hzmap`: геопривязки пока **не попадают на ПДА**, GPS-маркер и чтение LC76G в прошивке пока не реализованы.
4. Подключи верхний USB-C **J2** с передачей данных; введи ПДА в BOOT (BOOT + RST). Выбери COM-порт (автоматически — только если найден ровно один), нажми «ЗАПИСАТЬ ВСЕ ВКЛАДКИ НА ПДА». Программа не шьёт код: читает таблицу разделов и существующую LittleFS, сохраняет оригинальную копию в `Документы/HorizonBackups`, меняет файлы карт/стартовых точек, записывает только раздел данных и читает его обратно для сравнения. При ошибке не удаляй копию.
5. Редактор пробует карты размером до 720×480, затем до 600×400, затем до 480×320, пока **все** вкладки не поместятся и не останется ≥256 КиБ для пользовательских данных. Реальный результат и путь к копии показывает после отправки. При нехватке места даже на 480×320 **запись не начинается**. Отдельный файл обзора для карт 480×320 не нужен.

Вкладка — постоянный ID `0..255` (после удаления ID не выдаётся снова); порядок и название можно менять, не перемещая точки между этажами. Отправка заменяет *все* стартовые точки; созданные на ПДА/полученные точки других вкладок остаются. **Если вкладка удалена**, её свои/принятые точки на этом ПДА удаляются при следующей отправке проекта — это необратимо без резервной копии; программа спрашивает подтверждение. Чаты, настройки и другие вкладки остаются. Ссылки на оставшиеся точки открывают нужный этаж и запускают подсветку; ссылка на удалённую точку не открывает чужой этаж. Чтобы точки на разных ПДА совпадали, загружай на них один и тот же проект (одинаковые ID этажей); другой набор этажей не следует считать совместимым.

Формат `.hzmap` v2 — ZIP с `project.json` (`format: 2`, массив `tabs` с `id/name/points` и необязательным `anchors`, счётчик `next_id`) и `map<ID>.jpg`; v1 `map.jpg + points.json` открывается как одна вкладка ID 0. На ПДА `/hzmap/tabs.csv` — строки `ID|название` в порядке вкладок; отсутствие файла означает старую одиночную вкладку 0. Карта 0 остаётся `/hzmap/map.rgb565`, остальные `/hzmap/map1.rgb565` и т. д.; у карт >480 ширины есть `map*_preview.rgb565`. Стартовые точки — прежний `pois.csv` с восьмым полем `tab`; свои `my.csv` сохраняют `tab` двенадцатым, принятые `net.csv` — девятым. Старые строки без поля относятся к вкладке 0. Радио для вкладки 0 сохраняет `HZ:POI:`, остальных — `HZ:POI2:...|tab|chunk`; прошивки до 1.12 не распознают второй формат.

На CrowPanel новое окно, переключение, запись и работа с железом требуют проверки **на устройстве** до продажи. Не выбирай во флешере стирание данных, если нужно сохранить содержимое.

Если увидел ошибку «Чтение таблицы: esptool: 'NoneType' object has no attribute 'write'», это старая сборка оконного редактора: пересобери `build_map_studio.bat` и замени EXE. Ошибка возникала до чтения карты и записи данных. Прошивку 1.12.0.ZI на ПДА ради этой правки обновлять не требуется.

**Журнал записи (редактор 1.12.2):** когда нажимаешь «ЗАПИСАТЬ ВСЕ ВКЛАДКИ НА ПДА», на Windows открывается консоль с этапами чтения, резервного копирования, записи и проверки, а также выводом esptool. При запуске из обычной консоли используется уже открытая. Консоль остаётся до закрытия редактора: её можно свернуть, но крестик новой консоли отключён, чтобы случайно не оборвать запись. Результат и путь резервной копии также выводятся в основном окне. Версия прошивки остаётся 1.12.0.ZI; повторная прошивка не нужна.

**Данные привязки в `.hzmap` (студия 1.13.0):** поле `anchors` каждой вкладки содержит список `{"name":"Ратуша","x":100,"y":40,"lat":50.775345,"lon":6.083887}`. Старые проекты без поля открываются с пустыми списками. Привязки связаны с постоянным ID вкладки и сохраняются при перестановке; удаление вкладки или замена её JPG удаляет и её привязки (с подтверждением в окне). Диапазоны: широта от −90 до 90°, долгота от −180 до 180°; `NaN` и совпадающие опоры не допускаются. `tabs.csv`, `pois.csv`, RGB565 и резервная копия на ПДА не содержат координат. Чтобы сохранить опоры, храни исходный `.hzmap`: восстановить их из ПДА нельзя. Обычные игровые точки остаются отдельными и не считаются геопривязкой.
