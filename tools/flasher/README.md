# HorizonFlasher — полевая прошивка без VSCode и интернета

Прошивальщик ПДА «Горизонт» (ESP32-S3): окно «ZIP-пакет + порт + ПРОШИТЬ / ОБНОВИТЬ ДАННЫЕ»
(`HorizonFlasher.exe`) или консольный вариант (`HorizonFlasher-CLI.exe`) +
ZIP-файл прошивки. В поле нужен только USB-кабель и ноутбук с Windows —
ни GitHub, ни VSCode, ни PlatformIO, ни интернет.

## Подготовка дома (один раз + на каждую новую прошивку)

1. Собери прошивку: из корня репозитория `build.bat`, затем `package.bat`
   (подробности — в `fw/README.md`). Получится `horizon-<версия>.zip`.
   Вручную то же самое:
   ```powershell
   pio run -e elecrow-adv-35-tft
   pio run -e elecrow-adv-35-tft -t buildfs
   python tools\\flasher\\make_package.py --build firmware-hz\\.pio\\build\\elecrow-adv-35-tft --out horizon-1.7.0 --zip
   ```
   Скрипт сам найдёт оффсет файловой системы в `partitions.bin`, штатный
   `boot_app0.bin` во фреймворке и сложит рядом `flash.json`. Имя
   папки/архива = имя пакета (версия видна сразу).
2. Собери `.exe` (один раз; при обновлении редактора/прошивальщика — заново):
   запусти `tools\\flasher\\build_exe.bat` → получатся `dist\\HorizonFlasher.exe`
   (окно, продукт) и `dist\\HorizonFlasher-CLI.exe` (консоль). Скрипт сам
   выберет Python (предпочитает 3.13) и доустановит зависимости.
   Есть также сценарий `.github/workflows/horizon-flasher-windows.yml` для
   сборки в GitHub Actions, **если Actions включены и доступен Windows runner**.
   Пока сборка не завершилась успешно, готового `.exe` нет. Покупателю
   впоследствии нужен **только готовый `.exe`**, не Python.
3. На флешку: `HorizonFlasher.exe` + `horizon-1.7.0.zip` (+ `README-BUYER.txt`
   покупателю, см. ниже).

## В поле (на каждое устройство)

1. Подключи ПДА к ноутбуку ВЕРХНИМ USB-C (J2/OTG) кабелем **с данными**
   (charge-only не увидится; нижний J1/CH340 — только зарядка и логи,
   запись через него не идёт).
   Штатный USB ESP32-S3 подхватывается встроенным драйвером Windows 10/11,
   ничего ставить не надо; при первом подключении подожди 1-2 минуты.
   Встроенный USB не умеет автовход в download: зажми BOOT, коротко нажми
   RST и держи BOOT до старта записи.
2. Запусти `HorizonFlasher.exe` (двойной клик): кнопка «Обзор...» →
   выбери `horizon-<версия>.zip`, проверь порт (режим «Авто» сам найдёт плату),
   жми **ПРОШИТЬ**. Ход записи виден в логе окна и на полосе прогресса.
3. Дождись «ГОТОВО». Отключай, бери следующее устройство.

Ярлык на рабочий стол: правой кнопкой по `HorizonFlasher.exe` →
«Создать ярлык» → перетащить ярлык на рабочий стол. ZIP-пакеты
открываются из любого места кнопкой «Обзор...».

Запуск GUI из исходников дома: `python tools\\flasher\\flasher_gui.py` тем
интерпретатором, куда ставились зависимости (`requirements.txt`).
Консольный `HorizonFlasher-CLI.exe` (папка пакета + ключи ниже) остаётся
для скриптов и любителей терминала.

Радио на время прошивки отключать **не нужно** (single-MCU: на UART0
ничего нет). Обычная прошивка **сохраняет чаты, точки и настройки**: раздел
данных не записывается. Только явная галочка «СТЕРЕТЬ данные» записывает
чистую ФС из прошивочного пакета. Галочка «Стереть весь чип» также требует
явно выбрать очистку ФС. Для нового устройства используй обе галочки.

## Редактор карты в том же HorizonFlasher.exe

**ZIP и Python для редактора не нужны.** Запусти оконный `HorizonFlasher.exe`
и нажми «ОТКРЫТЬ РЕДАКТОР КАРТЫ И ТОЧЕК». Открой JPG **3:2 от 480×320 до 960×640, не больше 8 МиБ**;
если рядом лежит старый `pois.txt`, прежние стартовые точки загрузятся
автоматически с сохранением их порядка (`B001`, `B002`, …). Либо открой
сохранённый проект `.hzmap` (внутри картинки и точки, переносится одним файлом).
Новый RGB565 получается размером не более **720×480 (691 200 Б)**: JPG
624×416 отправится как 624×416, JPG 720×480 — как 720×480, старый проект
960×640 уменьшится при отправке. Положение точек сохранится.

Щёлкни на пустой карте, введи название, тип, автора и комментарий справа и
нажми «Добавить / сохранить точку». У уже созданной точки можно изменить
карточку, точные X/Y, передвинуть её мышкой или удалить. Справа список всех
точек; `+`/`−` меняют масштаб, масштаб редактора меняет только просмотр,
правая кнопка мыши двигает вид. Лимит — 50 стартовых точек; как и у ПДА,
доступны пять типов, название до 20 и комментарий до 150 символов.
Стартовые точки **общие**: личные и принятые из эфира точки редактор не
редактирует и при отправке не удаляет. Если начать с пустого JPG без
`pois.txt`/проекта, на ПДА окажутся **только** точки из нового проекта —
старые стартовые точки будут заменены, а не добавлены к нему.

Нажми «Сохранить проект», чтобы позже продолжить редактирование. Для отправки
подключи ПДА через J2, введи его в режим прошивки, проверь порт в главном
окне и нажми в редакторе «ЗАЛИТЬ КАРТУ И ТОЧКИ НА ПДА». **ZIP прошивки выбирать
не надо**: программа сама читает с ПДА таблицу разделов, делает карту/обзор
и `pois.csv`, затем использует защищённую процедуру ниже с резервной копией,
проверкой всех остальных файлов и повторным чтением. Код прошивки не
меняется. Для новых размеров нужна прошивка **1.8.6.ZI+**; на старой сначала обнови её
обычной прошивкой **без очистки данных**. Если ранее удалял встроенную точку
на ПДА, она может оставаться скрытой по старому ID (`del.csv` сохраняется).

## Отдельное обновление карты и стартовых точек

Если на **1.8.4.ZI** после загрузки карты экран дважды мигает и возвращается
в меню, сначала обнови **только прошивку до 1.8.5.ZI** без галочек очистки.
Карту и точки повторно заливать не нужно: они останутся в разделе данных.
В 1.8.5 карта открывается с маленького обзора; при нехватке памяти крупная
карта читается из ФС по строкам. Ошибка файла/памяти показывается на экране.

Для новых размеров поставь прошивку **1.8.6.ZI или новее** (обычная прошивка без галочек
сохранит данные и старую карту). Затем выбери *ZIP данных* и отметь
«Обновить карту» и/или «Обновить стартовые точки»; нажми «ОБНОВИТЬ
КАРТУ/ТОЧКИ». Это не записывает код прошивки. Старые чаты, собственные и
принятые точки, отметки удаления и настройки остаются на ПДА.

Собрать ZIP данных дома (после обычных двух команд `build.bat`, `package.bat`):

```powershell
python tools\flasher\make_data_package.py --partitions firmware-hz\.pio\build\elecrow-adv-35-tft\partitions.bin --game games\zabytye-istorii --out horizon-map-1.8.6.zip
```

Это один ZIP с картой, сглаженным обзором и стартовыми точками. Выбор
конкретных файлов делается в окне при заливке. Старый `pois.txt` записан в
координатах 480×320; конвертер сам переводит их в доли карты. Если *новый*
`pois.txt` уже записан в координатах самого JPG — добавь `--poi-coordinates map` (или, например, `--poi-coordinates 624x416`).
Передавай покупателю тот же `HorizonFlasher.exe` и ZIP данных, без установки
Python/PIO на его компьютер.

Процедура перед записью: сверить таблицу разделов на самом ПДА с пакетом,
считать весь раздел LittleFS (в таблице Meshtastic он называется `spiffs`), сохранить **оригинал** в
`Документы/HorizonBackups/hz-littlefs-*.bin`, смонтировать его без форматирования,
заменить только выбранные файлы, проверить контрольные суммы всех остальных
файлов, записать изменённый образ и прочитать его повторно для сравнения.
Если монтирование, размер, контрольные суммы или таблица разделов не сошлись —
запись не начинается. При обрыве кабеля во время записи восстановление может
потребовать резервную копию; не удаляй её и обратись к мастеру. Этот сценарий
проверен на синтетическом образе, но требует проверки на реальном ПДА и в
собранном Windows exe перед распространением. Не прерывай запись.


## Комплект покупателю (продажа в другой регион)

Покупателю уходят 3 файла: `HorizonFlasher.exe`, `horizon-<версия>.zip`,
`README-BUYER.txt` (лежит рядом, объясняет 2 кнопки человеческим языком).
Отправлять ссылкой на облако: `.exe` (~35 МБ) в почту не влезет.
Покупателю НЕ нужны Python, PlatformIO, VSCode, драйверы и интернет.
Единственный порог — SmartScreen при первом запуске («Подробнее» →
«Выполнить в любом случае», расписано в README-BUYER.txt); подпись
кода Authenticode — на будущее, не сейчас.

## Ключи (консольный вариант)

| Ключ | Что делает |
|---|---|
| `--package <папка>` | пакет прошивки (по умолчанию — автопоиск рядом) |
| `--port COMx` | порт вручную (по умолчанию — автоопределение) |
| `--baud 460800` | скорость ниже (при ошибках связи; можно и 115200) |
| `--list-ports` | показать порты и выйти |
| `--skip-fs` | прежний ключ, теперь необязателен: данные сохраняются по умолчанию |
| `--write-fs` | **очистить данные**: записать целый раздел ФС из ZIP |
| `--erase-all --write-fs` | стереть весь чип и записать чистую ФС (новое устройство) |
| `--no-pause` | не ждать Enter в конце (для скриптов) |

Примеры:
```powershell
HorizonFlasher-CLI.exe                      # обычная прошивка, данные сохраняются
HorizonFlasher-CLI.exe --erase-all --write-fs # чистое новое устройство
HorizonFlasher-CLI.exe --port COM5 --baud 460800   # ручной режим
```

## Состав пакета (справка)

`flash.json` + бинарники, оффсеты для CrowPanel 16 МБ (`default_16MB.csv`):

| Оффсет | Файл | Что это |
|---|---|---|
| `0x0` | `bootloader.bin` | загрузчик |
| `0x8000` | `partitions.bin` | таблица разделов |
| `0xe000` | `boot_app0.bin` | выбор app0 (штатный из фреймворка) |
| `0x10000` | `firmware.bin` | сама прошивка |
| `0xc90000` | `littlefs.bin` | файловая система (тег `fs`) |

Параметры flash: `dio/80m/16MB` (дефолт; QIO на этой плате даёт ROM-петлю — проверено), скорость по умолчанию `921600`.

## Диагностика

| Симптом | Причина и лечение |
|---|---|
| `не найдено COM-портов` | charge-only кабель / кабель в нижнем J1 вместо OTG (в списке только CH340 — переткни в верхний) / Windows ещё ставит драйвер (подожди 2 мин, жми «Обновить») |
| `Failed to connect` / вечное `Connecting...` | плату не ввели в download: зажать BOOT, коротко RST, держать BOOT до старта записи (окно само подскажет); fallback — другой кабель, скорость 460800 |
| `пакет прошивки не найден` | папка пакета должна лежать рядом с `.exe` и содержать `flash.json` |
| `в сборке нет файлов: littlefs.bin` | дома забыли `pio run -t buildfs` (или просто запусти `build.bat`) |
| Прошилось, но грузится старое | Проверь пакет и версию; полное стирание (`--erase-all --write-fs`) удалит все данные! |
| Окно упало без объяснений | полный текст — в свежем `%TEMP%\\hzflash-error-*.txt` |

## Разработчику

- Прошивальщик — тонкая обёртка над `esptool.main()` (пин `esptool>=5.6,<6`,
  CLI через дефис), автопорт — через `pyserial` (приоритет VID: `303A`
  штатный USB-Serial/JTAG самого S3 (= разъём J2/OTG, рабочий путь записи),
  затем `1A86` CH340 и `10C4` CP210x; выбор не-S3 подсвечивается
  подсказкой про J2).
- Ключ `--collect-data esptool` в `build_exe.bat` обязателен: без
  stub-загрузчиков (`esptool/targets/stub_flasher/*.json`) внутри `.exe`
  запись невозможна (esptool читает их с диска по `__file__`).
- `.exe` паковать UPX **нельзя**: Defender принимает UPX за вирус
  (ложные срабатывания у покупателей страшнее лишних мегабайт).
- Проверки без железа (чистый Python, ~секунда):
  `python tools/flasher/tests/test_flasher.py` (GUI-ядро, ZIP, сборщик пакета),
  `python tools/build/tests/test_build.py` (сборка в 2 команды, boot_app0),
  `python tools/flasher/tests/test_data_update.py` (LittleFS, сохранение, чтение назад),
  `python tools/flasher/tests/test_map_editor.py` (проект, точки, передача на эмуляцию ПДА).
