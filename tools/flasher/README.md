# HorizonFlasher — полевая прошивка без VSCode и интернета

Прошивальщик ПДА «Горизонт» (ESP32-S3): окно «ZIP-пакет + порт + ПРОШИТЬ»
(`HorizonFlasherGUI.exe`) или консольный вариант (`HorizonFlasher.exe`) +
ZIP-файл прошивки. В поле нужен только USB-кабель и ноутбук с Windows —
ни GitHub, ни VSCode, ни PlatformIO, ни интернет.

## Подготовка дома (один раз + на каждую новую прошивку)

1. Собери прошивку в дереве Meshtastic (после `overlay.py`, см. `fw/README.md`):
   ```powershell
   pio run -e elecrow-adv-35-tft
   pio run -e elecrow-adv-35-tft -t buildfs
   ```
2. Собери пакет прошивки (ключ `--zip` сразу делает архив для GUI):
   ```powershell
   python tools\flasher\make_package.py --build firmware-hz\.pio\build\elecrow-adv-35-tft --out horizon-1.7.0 --zip
   ```
   Скрипт сам найдёт оффсет файловой системы в `partitions.bin` и сложит
   рядом `flash.json`. Имя папки/архива = имя пакета (версия видна сразу).
   (Команда для корня репозитория; из `firmware-hz` путь `--build` короче.)
3. Собери `.exe` (один раз; при обновлении самого прошивальщика — заново):
   запусти `tools\flasher\build_exe.bat` → получатся `dist\HorizonFlasher.exe`
   (консоль) и `dist\HorizonFlasherGUI.exe` (окно). Скрипт сам выберет Python
   (предпочитает 3.13) и доустановит зависимости.
4. Скачай драйвер CH340 (WCH CH341SER.EXE) — он понадобится полевому
   ноутбуку, а там интернета не будет.
5. На флешку: `HorizonFlasherGUI.exe` + `horizon-1.7.0.zip` +
   установщик драйвера CH340.

## В поле (на каждое устройство)

1. Установи драйвер CH340 на ноутбук (один раз).
2. Подключи ПДА к ноутбуку **нижним USB-C (J1)** — верхние порты не подойдут.
   Кабель обязан быть с данными (charge-only не увидится).
3. Запусти `HorizonFlasherGUI.exe` (двойной клик): кнопка «Обзор...» →
   выбери `horizon-1.7.0.zip`, проверь порт (режим «Авто» сам найдёт CH340),
   жми **ПРОШИТЬ**. Ход записи виден в логе окна и на полосе прогресса.
4. Дождись «ГОТОВО». Отключай, бери следующее устройство.

Запуск GUI из исходников дома: `python tools\flasher\flasher_gui.py` тем
интерпретатором, куда ставились зависимости (`requirements.txt`).
Консольный `HorizonFlasher.exe` (папка пакета + ключи ниже) остаётся
для скриптов и любителей терминала.

Радио на время прошивки отключать **не нужно** (single-MCU: на UART0
ничего нет). История чатов на устройстве при обычной прошивке **стирается**
(льётся чистая ФС); чтобы сохранить данные — ключ `--skip-fs`.

## Ключи

| Ключ | Что делает |
|---|---|
| `--package <папка>` | пакет прошивки (по умолчанию — автопоиск рядом) |
| `--port COMx` | порт вручную (по умолчанию — автоопределение) |
| `--baud 460800` | скорость ниже (при ошибках связи; можно и 115200) |
| `--list-ports` | показать порты и выйти |
| `--skip-fs` | не трогать файловую систему (сохранить данные) |
| `--erase-all` | стереть весь чип перед записью (чистое устройство) |
| `--no-pause` | не ждать Enter в конце (для скриптов) |

Примеры:
```powershell
HorizonFlasher.exe --skip-fs              # обновить, сохранив чаты
HorizonFlasher.exe --erase-all            # новое/глючное устройство начисто
HorizonFlasher.exe --port COM5 --baud 460800   # ручной режим
```

## Состав пакета (справка)

`flash.json` + бинарники, оффсеты для CrowPanel 16 МБ (`default_16MB.csv`):

| Оффсет | Файл | Что это |
|---|---|---|
| `0x0` | `bootloader.bin` | загрузчик |
| `0x8000` | `partitions.bin` | таблица разделов |
| `0xe000` | `boot_app0.bin` | выбор app0 |
| `0x10000` | `firmware.bin` | сама прошивка |
| `0xc90000` | `littlefs.bin` | файловая система (тег `fs`) |

Параметры flash: `qio/80m/16MB`, скорость по умолчанию `921600`.

## Диагностика

| Симптом | Причина и лечение |
|---|---|
| `не найдено COM-портов` | нет драйвера CH340 / charge-only кабель / не тот USB (нужен J1) |
| `Failed to connect` / вечное `Connecting...` | плохой кабель; попробуй `--baud 460800`; fallback — зажать BOOT, коротко нажать RST, держать BOOT до старта записи |
| `пакет прошивки не найден` | папка пакета должна лежать рядом с `.exe` и содержать `flash.json` |
| `в сборке нет файлов: littlefs.bin` | дома забыли `pio run -t buildfs` |
| Прошилось, но грузится старое | сотри начисто: `--erase-all` |

## Разработчику

- Прошивальщик — тонкая обёртка над `esptool.main()` (пин `esptool>=5.6,<6`,
  CLI через дефис), автопорт — через `pyserial` (приоритет VID `1A86` CH340).
- Ключ `--collect-data esptool` в `build_exe.bat` обязателен: без
  stub-загрузчиков (`esptool/targets/stub_flasher/*.json`) внутри `.exe`
  запись невозможна (esptool читает их с диска по `__file__`).
- Проверка без железа: `flasher.py --help`, `--list-ports`, валидация
  манифеста на битом пакете; `make_package.py` — на синтетической сборке
  (парсинг `partitions.bin`, генерация `boot_app0.bin`).
