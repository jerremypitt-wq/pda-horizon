# Командирский планшет: CrowPanel Advance 7.0 (ESP32-S3) + Горизонт

Исследование от 26.10.2026: почему производитель пишет «не поддерживает
Meshtastic» для ревизий старше 1.1 и что нужно для порта Горизонта.
Вывод короткий: **портировать можно, запретов железа нет** — разница
ревизий закрывается ~200 строками кода + новой раскладкой UI под 800×480.

Брать только ESP32-S3 вариант (модель DIS02170A). Сейчас продаётся V1.4
(по железу и протоколу = V1.3). Вариант на ESP32-P4 (1024×600) —
другой SoC, не цель.

## Почему «не поддерживает Meshtastic»

Стоковый таргет `elecrow-adv1-43-50-70-tft` написан под V1.0:

- подсветка через расширитель PCA9557/TCA9534 (0x18), зуммер на GPIO8,
  сброс тача напрямую, LoRa CS на GPIO0 (с джампером, т.к. GPIO0 —
  кнопка BOOT/автопрограммирование).

Начиная с V1.2:

- подсветка/зуммер/сброс тача/усилитель переехали в управляющий
  микроконтроллер STC8H1K28 (I2C 0x30) с однобайтным протоколом:
  V1.2 — уровни 0x05 (выкл)…0x10 (макс, слать первым);
  V1.3+ — 0 (макс)…244 (мин), 245 (выкл), 246/247 (зуммер вкл/выкл),
  248 (вкл. усилитель), 250 (тач). Без него — чёрный экран и тишина.
- LoRa CS переехал с GPIO0 на GPIO8 (зуммер ушёл в STC, пин
  освободился). Остальное радио не менялось.
- Пины 4/5/6 (SPI/I2S/SD) и 19/20 коммутируются DIP S0/S1 через ключ
  CH486F: `00` MIC&SPK, `01` wireless, `10` TF, (`11` MIC&TF).
  LoRa и TF-карта на одних пинах — одновременно нельзя (это и есть
  «техническое ограничение» из ответа Elecrow). Для радио: S0/S1 = 01.

«Не будет поддерживаться» — позиция Elecrow (коллаборация была только
под V1.0, продукт так и не выпустили), а не физика: энтузиаст уже
завёл MUI на V1.4/V1.5 (meshtastic/firmware#11393).

## Почему Горизонту проще, чем стоковому MUI

- TF-карта не нужна (история/конфиг во внутренней LittleFS) —
  ограничение «LoRa xor TF» нас не касается. DIP в 01 и забыть.
- Усилитель/микрофон не нужны (звук — зуммер через STC 246/247).
- Дисплей/тач/радио — известные пины, конфиги есть в примерах Elecrow.

## Распиновка 7.0 V1.3+ (сводно, для порта)

- SoC ESP32-S3-WROOM-1-N16R8 (16 МБ flash, 8 МБ PSRAM).
- Дисплей 800×480 RGB565: данные B 21/47/48/45/38, G 9/10/11/12/13/14,
  R 7/17/18/3/46; DE 42, VSYNC 41, HSYNC 40, PCLK 39; 18 МГц;
  фреймбуфер в PSRAM (750 КБ). Конфиг LovyanGFX — копипаст
  из `LovyanGFX_Driver.h` примера Elecrow (Bus_RGB + Panel_RGB).
- Тач GT911: SDA15/SCL16, адрес 0x5D, INT→GPIO1, RST через STC.
- STC8H1K28: I2C 15/16, адрес 0x30 (см. команды выше).
- Радио (слот, DIP 01): SPI SCK5/MISO4/MOSI6, CS **GPIO8**,
  DIO1 20, RST 19, BUSY 2. Модуль SX1262 — тот же, что на 3.5".
- Свободный I2C наружу: J13 (SDA15/SCL16/3V3/GND, общая шина с тачем,
  STC и RTC) — сюда просится MAX17048 (адрес 0x36 не конфликтует).
- RTC PCF8563 + CR1220 на шине (адрес 0x51) — по схеме есть, кодом
  Elecrow не проверен: при получении платы проверить сканом.
  Если жив — у планшета настоящие часы (бонус для Горизонта).
- Батарея: разъём + TP4059 как на 3.5"; CHRG/DONE заведены в STC
  (напрямую ESP32 их не видит). Делитель с J15 3.5" НЕ переносится:
  GPIO17/18 на 7" — данные RGB; проценты — только через MAX17048.
- Внимание: J15 на 7" — это разъём динамика, а не GPIO!

## Хранилище данных (карты/документы): TF невозможна

TF-слот и радиослот делят пины 4/5/6 (и 19/20) через два ключа CH486F
(U9/U11), выбор канала — ТОЛЬКО механическим DIP (K1): на линиях SEL0/SEL1
по схеме V1.5 висят лишь DIP, подтяжки и сами ключи, GPIO ESP32 нет.
Одновременная работа LoRa + TF на стоковом железе невозможна в принципе
(переключать DIP на лету — не вариант; делить SPI между RadioLib
с прерываниями и SD-стеком — тем более).

План вместо TF:

- Данные (карта, документы) — во внутренней flash: своей таблицей
  разделов отдать под LittleFS 6–10 МБ из 16 МБ (второй OTA-слот ужать;
  планшет шьётся по USB со стенда). Арифметика: приложение сейчас 2.5 МБ
  при разделах app0/app1 по 6.5 МБ — ужатие каждого до 3.5 МБ даёт
  ~9.4 МБ данных; отказ от OTA (один app-слот) — ~12 МБ.
  Ориентиры: векторная карта полигона — сотни КБ; страница A4 в JPEG
  800×480 — 30–80 КБ (100 страниц ≈ 5 МБ). Заявленным фичам хватит.
- Если 16 МБ всё же мало (лестница): 1) сжатие/форматы (JPEG, вектор) —
  на порядок; 2) докачка по WiFi с телефона/ноутбука (тонкий клиент +
  кэш в LittleFS/PSRAM); 3) смена платы — только если нужны сотни МБ
  (спутниковые тайлы большой площади): критерий — SD на отдельной шине
  + RGB + свободный SPI под радио. Не варианты: замена flash в модуле
  (пайка модуля), TF+радио (доказано выше), USB-флешка (D+/D− заняты
  радио), I2C-FRAM (+1 МБ дорого — овчинка не стоит).
- Заливка контента: `uploadfs` из папки `data/` по USB; позже —
  WiFi-AP планшета с веб-заливкой через браузер ноутбука.
- Карта полигона — свой векторный формат (полигоны/точки/сетка),
  рендер на LovyanGFX/LVGL; позиции узлов берутся из nodeDB меша
  (планшет — узел сети, GPS-железо не нужно) → живые метки своих.
- PDF — без нативного движка (тяжёл для MCU): PC-утилита режет PDF
  в постраничные PNG/тайлы, на планшете — листалка с зумом/паном.
- Отвергнуто: I2C-FRAM (мало/дорого), USB-OTG флешка (D+/D− это
  GPIO19/20 — заняты радио; разъёмы не разведены), внешний SPI-flash
  (свободных пинов нет).

## Объём порта (оценка)

1. Конфиг панели 7" (LGFX RGB + GT911 + тайминги) — по примеру, 1–2 дня.
2. Драйвер STC (подсветка/зуммер/сон) + тесты по нашей схеме — ~200 строк.
3. Радио: CS=8; сборка тем же оверлеем (новый таргет/вариант).
4. **Раскладка UI под 800×480 — основная работа.** UI свёрстан под
   480×320; на 7" просятся двухпанельные экраны (список+чат рядом) —
   для командирского это плюс, но это недели вечеров, а не дни.
5. Опционально: MAX17048 на J13 (батарея), RTC 0x51 (часы).
