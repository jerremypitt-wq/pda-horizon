# Карта для игры «Забытые истории» (прошивка 1.9.0.ZI)

Спека фичи. Стек — нынешний (Meshtastic-радио): точки ездят маяками в текстовых каналах,
как досье. GPS нет и не нужен: точки живут в пикселях картинки.

Решения владельца (зафиксированы): JPG 3:2 до 960×640, на ПДА не более 720×480, экран 480×320 + лупа «+»/«−» + двигание;
удаление общих — автор или ранг «мастер» (3); правки — только свои;
50 общих + 10 своих; название 20 / комментарий 150 символов; типы: Точка интереса,
База, Опасность, Аномалия, Схрон. Исходники — `docs/MAP_ORDER.md`, пакет — `games/zabytye-istorii/`.

## 1. Файлы и форматы

### 1.1. Исходники поставщика → build-файлы (конвертер `tools/build/poi_pack.py`)

| Исходник | Проверка | Build-файл |
|---|---|---|
| `map.jpg` | JPG 3:2 от 480×320 до 960×640, до 8 МиБ | `map.rgb565` — RGB565 LE исходного размера или уменьшенный до 720×480 (не более 691 200 Б); `map_preview.rgb565` — обзор 480×320, 307 200 Б |
| `pois.txt` | типы из списка 5; имя ≤20; коммент ≤150; X 0–479, Y 0–319; без `\|` и переводов строк; точек ≤50 | `pois.csv` — строки `id\|type\|name\|x\|y\|sender\|comment`, координаты в тысячных долях |

Тысячные доли: `pm = round(px*1000/479)` для X, `round(py*1000/319)` для Y.
Исходный `pois.txt` использует **старые координаты 480×320**: `x = round(px*1000/479)`, `y = round(py*1000/319)`. Редактор хранит координаты в пикселях исходного JPG и переводит их в тысячные доли перед отправкой. Для `pois.txt` в пикселях исходного JPG укажи `--poi-coordinates map` (или явно `624x416`). Точки, созданные на самом ПДА, всегда хранят доли и сохраняют положение при смене размера карты.
ID стартовых точек: `B001`, `B002`, … по порядку файла.

### 1.2. Файлы на устройстве (LittleFS, каталог `/hzmap/`)

| Файл | Кто пишет | Что внутри |
|---|---|---|
| `map.rgb565` | пакет/отдельное обновление | новый файл 3:2 от 480×320 до 720×480; прошивка также читает старый 960×640 |
| `map_preview.rgb565` | пакет/отдельное обновление | сглаженный обзор при масштабе 1×; необязателен для старой карты |
| `pois.csv` | пакет/отдельное обновление | стартовые общие точки |
| `my.csv` | ПДА | свои и полученные лично копии: `id|type|name|x|y|sender|comment|shared|ch|peer|sourceId`; старые 9/10 полей читаются |
| `net.csv` | ПДА | принятые из эфира общие точки (тот же формат без shared) |
| `del.csv` | ПДА | ID удалённых запечённых точек (могилы, чтобы не воскресали после ребута) |
| `dm_del.csv` | ПДА | исходные ID лично присланных точек, удалённых получателем; повторы их не восстановят |

Общий пул = запечённые (минус могилы) + принятые + свои-с-флагом-shared. Лимит 50:
при переполнении — тост «Нет места для точек» и отказ (предсказуемо, решает мастер игры).
Приватных (`my.csv`, shared=0) — лимит 10.

### 1.3. Типы точек (в эфир едет индекс)

0 = Точка интереса, 1 = База, 2 = Опасность, 3 = Аномалия, 4 = Схрон.

## 2. Эфир (маяки в текстовых каналах)

Всё — обычными сообщениями в канал (Общий или Группировка — выбирается при создании точки,
по умолчанию Общий). ПДА перехватывают по префиксу, человек их не видит
(как `HZ:DOSSIER:`). Свои эхи (ID своего авторства) игнорируются. Дедуп — по ID.

Бюджет: каждое сообщение ≤220 байт (наш же лимит пакета — 230, запас 10).
Поля `name`/`sender`/`comment` — без `|` и переводов строк (на вводе правим в пробел).

### 2.1. Точка (возможно, в нескольких частях)

Часть 1 (есть всегда):
```
HZ:POI:<id>|<total>|<idx>|<type>|<name>|<x>|<y>|<sender>|<chunk1>
```
- `total` — всего частей, `idx` — номер этой (с 1). Одна часть: `total=1,idx=1`.
- `x`,`y` — тысячные доли 0–1000. `sender` — позывной, обрезанный до 20 символов.
- `chunk` — кусок комментария ≤100 байт, рез строго по границе UTF-8.

Худший случай: 8 (префикс) + 12 (id) + ~10 (числа) + 40 (имя) + 4+4 + 40 (sender) +
8 (разделители) + 100 = 226… больше 220! Поэтому чанк — **≤96 байт**, итого ≤220. ✓
Комментарий 150 букв кириллицы (300 байт) едет 4 частями. Запечённые 3 точки — по 1 части.
Чанк подгоняется под шапку динамически (всегда ≤96, чтобы часть влезла в 220 при любых
именах); частей максимум 8, хвост за 8 частями отбрасывается (в лог). Приём при полном
пуле — молча в лог (тост на каждый чужой маяк был бы спамом).

Повторная отправка того же ID = обновление (затирает) при совпадении автора.
Сборка: буфер по ID, таймаут 120 с — не собралось → выкинуть молча.
После сборки — проверка (тип 0–4, доли 0–1000, длины) → в `net.csv` → тост «Точка: <имя>».

### 2.2. Удаление

```
HZ:POID:<id>|<node>|<rank>
```
`node` — NodeID удаляющего, `rank` — его заявленный ранг. Принимаем, если:
- `node` == автор точки (свой ID помним; у запечённых автор — «мастер», node 0), ИЛИ
- ранг удаляющего == 3 (Мастер) по кэшу досье; нет в кэше — принимаем на веру (игра,
  задокументировано; поднять себе ранг без мастер-PIN нельзя — досье под PIN).

Удаление запечённой точки = запись ID в `del.csv` (могила) + стирание из пула.
Удаление принятой/своей = стирание из `net.csv`/`my.csv`. Свои удалённые shared-точки
шлют `HZ:POID` в тот же канал, куда слалась точка (канал помним в `my.csv`? нет —
шлём в Общий всегда? РЕШЕНО: удаление шлётся в тот же канал; канал хранится 9-м полем
`my.csv`/`net.csv`). Значит формат файлов: `...|comment|shared|ch` и `...|comment|ch`, плюс у `my.csv`
10-е поле `|peer` (DM-получатель, см. §2.4).
У запечённых своего канала нет — их удаление шлётся в Общий.

### 2.3. ID живых точек

`<nodeid>-<seq>`: десятичный NodeID автора + `-` + счётчик устройства (u16, хранится
в конфиге `poiSeq`, инкремент на каждую созданную точку). Пример: `2411905644-7`.

### 2.4. Точка в личку (DM)

При выборе «Поделиться» выбирается контакт. Исходная точка едет лично теми же
частями `HZ:POI:`; после частей обычным текстом отправляется
`HZ:MAPLINK:<id>|<название>` — ссылка сохраняется в истории обоих участников.
На приёмной стороне точка получает собственный ID в `my.csv`, исходный ID —
в поле `sourceId`. В карточке «Автор» остаётся отправитель. Получатель может
править содержимое и удалить копию локально: чужие правки/удаление исходника
её не меняют; собственная правка копии не уходит отправителю. Повтор того же
исходного ID не пересоздаёт копию после её удаления (`dm_del.csv`).
Публичные точки остаются в `net.csv` и получателю недоступны для правки.
Старые `net.csv` не указывают, что точка приехала лично: достоверно отличить
её от общей задним числом нельзя; новые личные точки работают по новым правилам.

## 3. Экран «Карта»

Плитка разблокирована. При открытии загружается обзор 480×320, полный исходник — лишь при увеличении и наличии памяти; иначе строки читаются из LittleFS.

- **Просмотр:** экран карты временно переключается в альбомную ориентацию даже
  при книжной настройке; при выходе настройка восстанавливается. Картинка
  заливает весь экран, включая область под тёмным полупрозрачным статусбаром, без полей
  (cover: лишнее обрезается и доступно двигом). Маркеры — цветные точки без подписей;
  цвета: Точка интереса жёлтый, База зелёный, Опасность красный, Аномалия фиолетовый,
  Схрон синий. «<» — слева сверху под статусбаром, кнопка-воронка фильтров — справа сверху,
  лупа «+»/«−» — слева посередине.
- **Фильтры:** панель с разделами «По типу» (5 видов точек) и «По доступу»
  (Общие/Личные), со счётчиками и галочками; применяется сразу, внизу «Сбросить все».
- **Зум:** кнопки лупа «+»/«−», уровни 1x / 1.5x / 2x / 3x. Пересчёт маркеров за видом.
- **Двигание:** тач-драг по карте. Маркеры и бирка едут с картой.
- **Тап по точке:** первый — бирка с именем, второй — карточка (имя, автор,
  комментарий, кнопки).
- **Двойной тап по пустому:** форма «новая точка» (имя + клавиатура, тип-список,
  комментарий, список «Публичная/Частная/Поделиться»; при публичной —
  «Кому видна точка»: Общая/Группировка, при «Поделиться» — выбор контакта).
  Для Новичка и Опытного «Общая» недоступна даже при правке старой точки;
  в общий канал метку отправить нельзя. Клавиатура формы закрывается кнопкой OK
  в правом нижнем углу, «<<» находится слева от неё.
- **Правка:** свои и независимые лично полученные копии; автор копии сохраняется.
  Общие чужие точки править нельзя.
- **Удаление:** свои — всегда; чужие общие — только при `cfg.rank == 3` (строго Мастер;
  в отличие от объявлений, где пускают с Ветерана, — так решил владелец).
- **Ссылки/уведомления:** тап открывает карту, центрирует точку и запускает
  пять волн расходящихся колец через 0,5 с. Если ссылка пришла раньше частей,
  после сборки точка подсветится автоматически.
- **Тосты:** «Точка: <имя>» (приём), «Нет места для точек» (пул полон),
  «Точка удалена», «Нет связи» (отправка без радио).

## 4. Версия и пакет

`kFirmwareVersion = "1.9.0.ZI"`. Пакет `horizon-1.9.0.ZI.zip` (DIO по умолчанию).
Штамп/сверка версий работают как обычно (строки сравниваются целиком).

## 5. План проверки (на железе, 2 ПДА)

1. Карта открывается, 3 запечённые точки на местах, зум/драг работают.
2. Создать общую → появилась на втором ПДА с именем/комментом/автором.
3. Длинный комментарий (150 букв) → доехал целым (4 части).
4. Удалил автор → пропало на обоих. Удалил мастер чужую → пропало.
   Удалил немajстер чужую → кнопки нет / команда отвергнута.
5. Ребут обоих → точки на месте (свои + принятые + могилы).
6. Пул полон (50) → отказ с тостом.
7. На первом ПДА выбрать «Поделиться» и контакт второго: в его личном чате
   появляется ссылка с названием. Нажать ссылку и уведомление о точке отдельно:
   карта центрируется, видны пять колец с шагом 0,5 с; повторить с задержкой
   доставки частей точки после ссылки.
8. На втором ПДА изменить лично полученную точку: автор прежний. Удалить
   оригинал на первом ПДА: копия второго остаётся и после перезагрузки.
   Удалить копию на втором: повторный приём её не восстанавливает.
9. Опубликовать автором ту же точку в общий канал: другой ПДА не может её
   править; личную копию можно править независимо. Проверить режимы формы:
   «Кому видна точка» только для публичной, контакт только при «Поделиться».

## 1.8.4: изменение данных без очистки

Новая прошивка сохраняет раздел данных по умолчанию и продолжает читать прежнюю карту 480×320. ZIP данных создаётся `tools/flasher/make_data_package.py` и загружается тем же GUI. Карта 960×640 введена в 1.8.4, но её открытие исправлено в 1.8.5.ZI. Сначала обновить прошивку без очистки, потом при необходимости отдельно карту/точки. Обновляются только `map.rgb565` + `map_preview.rgb565` и/или `pois.csv`; `my.csv`, `net.csv`, `del.csv`, `dm_del.csv` и чаты остаются. Процедура с резервной копией и проверкой описана в `tools/flasher/README.md`. Жесты двумя пальцами пока не реализованы.

## 1.8.5: карта после обновления данных

На 1.8.4 устройство могло сразу вернуть меню после касания «Карта»,
когда не находило непрерывные 1,2 МБ PSRAM под исходник 960×640. В 1.8.5
открытие использует сглаженный обзор 480×320 и буфер экрана (без большого
исходника). При зуме попытка загрузить 1,2 МБ необязательна: при нехватке
памяти строки читаются прямо из LittleFS. Проверка размера файла и сообщение
об ошибке видны на экране вместо краткого мигания. При сбое монтирования ФС
не форматируется автоматически: чаты и личные данные не должны стираться.
Для этого исправления была нужна **1.8.5.ZI** (текущая версия исходников — 1.9.0.ZI); карту/точки повторно заливать не требуется,
если они уже находятся на ПДА. Прошивать без галочек очистки. Реальные
компиляция и тест на устройстве обязательны перед распространением.

## 1.8.6: меньшие карты и разные размеры JPG

Редактор принимает JPG строго 3:2 от 480×320 до 960×640, файл до 8 МиБ.
Карта 624×416 (1,3×) записывается без изменения размера, 720×480 (1,5×)
тоже. Более крупный JPG, включая старые проекты 960×640, уменьшается до
720×480 при отправке: сохранённые точки остаются на своих местах благодаря
тысячным долям. Новый `map.rgb565` не превышает 691 200 Б; обзор всегда
480×320. Прошивка 1.8.6 определяет размеры из длины RGB565 при строгом
соотношении 3:2 и читает **старые** файлы 960×640 без перезаливки.
Новый размер требует прошивки 1.8.6.ZI; сначала прошить её без очистки
данных, потом при желании отправить меньшую карту. Чаты, свои и принятые
точки при этом не заменяются. Тесты кода не заменяют проверку на ПДА.

## 1.8.7: читаемый статус над картой

На экране карты верхняя полоса статуса шириной во весь экран и высотой 22 пикселя
получила тёмный фон с прозрачностью 40 % (непрозрачность 60 %). Белые надписи
читаются на светлых участках карты; сама карта всё ещё заполняет экран под
полосой. Остальные экраны и файлы карты не меняются: при обычной прошивке
без очистки повторно отправлять карту и точки не требуется.
