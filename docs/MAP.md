# Карта для игры «Забытые истории» (прошивка 1.8.4.ZI)

Спека фичи. Стек — нынешний (Meshtastic-радио): точки ездят маяками в текстовых каналах,
как досье. GPS нет и не нужен: точки живут в пикселях картинки.

Решения владельца (зафиксированы): исходник карты 960×640, экран 480×320 + лупа «+»/«−» + двигание;
удаление общих — автор или ранг «мастер» (3); правки — только свои;
50 общих + 10 своих; название 20 / комментарий 150 символов; типы: Точка интереса,
База, Опасность, Аномалия, Схрон. Исходники — `docs/MAP_ORDER.md`, пакет — `games/zabytye-istorii/`.

## 1. Файлы и форматы

### 1.1. Исходники поставщика → build-файлы (конвертер `tools/build/poi_pack.py`)

| Исходник | Проверка | Build-файл |
|---|---|---|
| `map.jpg` | ровно 960×640 | `map.rgb565` — 1 228 800 байт RGB565 LE; `map_preview.rgb565` — сглаженный обзор 480×320, 307 200 байт |
| `pois.txt` | типы из списка 5; имя ≤20; коммент ≤150; X 0–479, Y 0–319; без `\|` и переводов строк; точек ≤50 | `pois.csv` — строки `id\|type\|name\|x\|y\|sender\|comment`, координаты в тысячных долях |

Тысячные доли: `pm = round(px*1000/479)` для X, `round(py*1000/319)` для Y.
Исходный `pois.txt` использует **старые координаты 480×320**. Переводим в доли до отрисовки на 960×640: `x = pm*959/1000`, `y = pm*639/1000`. Для новых исходных точек в координатах 960×640 есть `--poi-coordinates 960x640` (знаменатели 959 и 639). Точки, созданные на самом ПДА, всегда хранят доли, поэтому сохраняют положение при смене размера карты.
ID стартовых точек: `B001`, `B002`, … по порядку файла.

### 1.2. Файлы на устройстве (LittleFS, каталог `/hzmap/`)

| Файл | Кто пишет | Что внутри |
|---|---|---|
| `map.rgb565` | пакет/отдельное обновление | картинка 960×640; прошивка принимает и прежний файл 480×320 |
| `map_preview.rgb565` | пакет/отдельное обновление | сглаженный обзор при масштабе 1×; необязателен для старой карты |
| `pois.csv` | пакет/отдельное обновление | стартовые общие точки |
| `my.csv` | ПДА | свои точки: `id\|type\|name\|x\|y\|sender\|comment\|shared` (`shared` 0/1) |
| `net.csv` | ПДА | принятые из эфира общие точки (тот же формат без shared) |
| `del.csv` | ПДА | ID удалённых запечённых точек (могилы, чтобы не воскресали после ребута) |

Общий пул = запечённые (минус могилы) + принятые + свои-с-флагом-shared. Лимит 50:
при переполнении — тост «Нет места для точек» и отказ (предсказуемо, решает мастер игры).
Приватных (`my.csv`, shared=0) — лимит 10.

### 1.3. Типы точек (в эфир едет индекс)

0 = Точка интереса, 1 = База, 2 = Опасность, 3 = Аномалия, 4 = Схрон.

## 2. Эфир (маяки в текстовых каналах)

Всё — обычными сообщениями в канал (Общий или Группировка — выбирается при создании точки,
по умолчанию Общий). ПДА перехватывают по префиксу, человек их не видит
(как `HZ:DOSSIER:`). Свои эхи (ID своего авторства) игнорируются. Дедуп — по ID.

Бюджет: каждое сообщение ≤220 байт (наш же лимит пакета — 230, запас 10).
Поля `name`/`sender`/`comment` — без `|` и переводов строк (на вводе правим в пробел).

### 2.1. Точка (возможно, в нескольких частях)

Часть 1 (есть всегда):
```
HZ:POI:<id>|<total>|<idx>|<type>|<name>|<x>|<y>|<sender>|<chunk1>
```
- `total` — всего частей, `idx` — номер этой (с 1). Одна часть: `total=1,idx=1`.
- `x`,`y` — тысячные доли 0–1000. `sender` — позывной, обрезанный до 20 символов.
- `chunk` — кусок комментария ≤100 байт, рез строго по границе UTF-8.

Худший случай: 8 (префикс) + 12 (id) + ~10 (числа) + 40 (имя) + 4+4 + 40 (sender) +
8 (разделители) + 100 = 226… больше 220! Поэтому чанк — **≤96 байт**, итого ≤220. ✓
Комментарий 150 букв кириллицы (300 байт) едет 4 частями. Запечённые 3 точки — по 1 части.
Чанк подгоняется под шапку динамически (всегда ≤96, чтобы часть влезла в 220 при любых
именах); частей максимум 8, хвост за 8 частями отбрасывается (в лог). Приём при полном
пуле — молча в лог (тост на каждый чужой маяк был бы спамом).

Повторная отправка того же ID = обновление (затирает) при совпадении автора.
Сборка: буфер по ID, таймаут 120 с — не собралось → выкинуть молча.
После сборки — проверка (тип 0–4, доли 0–1000, длины) → в `net.csv` → тост «Точка: <имя>».

### 2.2. Удаление

```
HZ:POID:<id>|<node>|<rank>
```
`node` — NodeID удаляющего, `rank` — его заявленный ранг. Принимаем, если:
- `node` == автор точки (свой ID помним; у запечённых автор — «мастер», node 0), ИЛИ
- ранг удаляющего == 3 (Мастер) по кэшу досье; нет в кэше — принимаем на веру (игра,
  задокументировано; поднять себе ранг без мастер-PIN нельзя — досье под PIN).

Удаление запечённой точки = запись ID в `del.csv` (могила) + стирание из пула.
Удаление принятой/своей = стирание из `net.csv`/`my.csv`. Свои удалённые shared-точки
шлют `HZ:POID` в тот же канал, куда слалась точка (канал помним в `my.csv`? нет —
шлём в Общий всегда? РЕШЕНО: удаление шлётся в тот же канал; канал хранится 9-м полем
`my.csv`/`net.csv`). Значит формат файлов: `...|comment|shared|ch` и `...|comment|ch`, плюс у `my.csv`
10-е поле `|peer` (DM-получатель, см. §2.4).
У запечённых своего канала нет — их удаление шлётся в Общий.

### 2.3. ID живых точек

`<nodeid>-<seq>`: десятичный NodeID автора + `-` + счётчик устройства (u16, хранится
в конфиге `poiSeq`, инкремент на каждую созданную точку). Пример: `2411905644-7`.

### 2.4. Точка в личку (DM)

Назначение общей точки: Общий канал / Группировка / «Отправить контакту» (выбор
из контактов). DM едет тем же `HZ:POI:`/`HZ:POID:`, но `to=<узел>` (перехват — без
проверки `to`, история чата маяками не засоряется). Канал DM — как у чата с узлом.
`my.csv`: 10-е поле `|peer` (0 = всем в канал); файлы ≤1.8.1 (9 полей) читаются.

## 3. Экран «Карта»

Плитка разблокируется (тост «появится позже» убрать). Открытие: чтение `/hzmap/*` в память.

- **Просмотр:** экран карты временно переключается в альбомную ориентацию даже
  при книжной настройке; при выходе настройка восстанавливается. Картинка
  заливает весь экран, включая область под прозрачным статусбаром, без полей
  (cover: лишнее обрезается и доступно двигом). Маркеры — цветные точки без подписей;
  цвета: Точка интереса жёлтый, База зелёный, Опасность красный, Аномалия фиолетовый,
  Схрон синий. «<» — слева сверху под статусбаром, «Фильтры» — справа сверху,
  лупа «+»/«−» — слева посередине.
- **Фильтры:** панель с разделами «По типу» (5 видов точек) и «По доступу»
  (Общие/Личные), со счётчиками и галочками; применяется сразу, внизу «Сбросить все».
- **Зум:** кнопки лупа «+»/«−», уровни 1x / 1.5x / 2x / 3x. Пересчёт маркеров за видом.
- **Двигание:** тач-драг по карте. Маркеры и бирка едут с картой.
- **Тап по точке:** первый — бирка с именем, второй — карточка (имя, автор,
  комментарий, кнопки).
- **Двойной тап по пустому:** форма «новая точка» (имя + клавиатура, тип-список,
  комментарий, список «Публичная/Частная», при публичной — назначение:
  Общая/Группировка/«Отправить контакту» с выбором из контактов).
- **Правка:** только свои (чужие — кнопки правки нет).
- **Удаление:** свои — всегда; чужие общие — только при `cfg.rank == 3` (строго Мастер;
  в отличие от объявлений, где пускают с Ветерана, — так решил владелец).
- **Тосты:** «Точка: <имя>» (приём), «Нет места для точек» (пул полон),
  «Точка удалена», «Нет связи» (отправка без радио).

## 4. Версия и пакет

`kFirmwareVersion = "1.8.4.ZI"`. Пакет `horizon-1.8.4.ZI.zip` (DIO по умолчанию).
Штамп/сверка версий работают как обычно (строки сравниваются целиком).

## 5. План проверки (на железе, 2 ПДА)

1. Карта открывается, 3 запечённые точки на местах, зум/драг работают.
2. Создать общую → появилась на втором ПДА с именем/комментом/автором.
3. Длинный комментарий (150 букв) → доехал целым (4 части).
4. Удалил автор → пропало на обоих. Удалил мастер чужую → пропало.
   Удалил немajстер чужую → кнопки нет / команда отвергнута.
5. Ребут обоих → точки на месте (свои + принятые + могилы).
6. Пул полон (50) → отказ с тостом.

## 1.8.4: изменение данных без очистки

Новая прошивка сохраняет раздел данных по умолчанию и продолжает читать прежнюю карту 480×320. ZIP данных создаётся `tools/flasher/make_data_package.py` и загружается тем же GUI. Карта 960×640 требует прошивку не старее 1.8.4.ZI; сначала обновить прошивку, потом отдельно карту/точки. Обновляются только `map.rgb565` + `map_preview.rgb565` и/или `pois.csv`; `my.csv`, `net.csv`, `del.csv` и чаты остаются. Процедура с резервной копией и проверкой описана в `tools/flasher/README.md`. Жесты двумя пальцами пока не реализованы.
