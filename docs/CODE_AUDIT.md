# Ревизия репозитория «Горизонт» — прошивка 1.15.1

## Что охвачено

Проверены состояние ветки и отслеживаемые файлы, пути сборки/упаковки,
прошивка (`src/horizon`, включая настройки, хранилища, карту, UI, звук,
батарею и приём пакетов), вспомогательные Python-скрипты, существующие
контрактные и хост-тесты. Исходники библиотеки Meshtastic protobuf в `lib/mesh/generated`
сгенерированы; они не переписывались. Скрипты PlatformIO получают `Import`
и `env` от SCons — сообщения статического линтера об этих именах не являются
ошибкой самостоятельного запуска Python. Флешер и его встроенный редактор
не менялись.

Это **статическая ревизия и хост-проверки**, а не доказательство отсутствия
всех дефектов в ~20 тыс. строк исходников. Не было анализа всей сторонней
прошивки Meshtastic, сборки прошивки, осциллограммы или испытания CrowPanel.

## Подтверждённые проблемы и исправления

| Место | Что было | Что сделано |
| --- | --- | --- |
| `HorizonMap.cpp` | `strtoul` приводился к `uint32_t` без проверки диапазона: число больше 2³²−1 могло стать допустимым типом, координатой или вкладкой. | Строгий разбор десятичных цифр с проверкой переполнения до приведения. |
| `HorizonMap.cpp`, `HorizonConfig.cpp` | Слишком длинная строка файла читалась по кускам. Её остаток мог выглядеть как отдельная корректная точка, вкладка, удалённый ID или настройка. | Строка целиком пропускается, включая остаток до перевода строки. Нормальные строки читаются как раньше. |
| `HorizonConfig.cpp` | `atoi` не проверял хвост и диапазон числа; переполнение выходило за его контракт. | `strtol` с проверкой хвоста и переполнения; допустимые числа по-прежнему ограничиваются существующими пределами. |
| `tools/build/tests/test_build.py`, `test_poi.py` | Фиксированные каталоги в `/tmp`: параллельные проверки мешали друг другу, а `test_build.py` удалял каталог с предсказуемым именем. | Уникальные временные каталоги, очистка после завершения; временная подмена `mkstemp` теперь восстанавливается. |
| `tools/tests/test_security_ui_contract.py`, `README.md` | Проверка требовала давно устаревшую версию `1.13.1.ZI`; README называл `1.14.0` текущей. | Проверка согласованности версии с документацией, актуальная версия `1.15.1`. |
| `bin/make_logo.py` | Генератор логотипа всегда записывал отладочный файл по Unix-пути `/tmp`, в том числе при запуске на Windows. | Убрана побочная запись, распутаны сокращённые имена переменных. |

Правки поведения прошивки выпущены как **1.15.1**; формат пользовательских
файлов, GPS и порядок очистки истории не менялись. Для новой защиты есть
хост-тесты с переполненными числами и длинными строками.

## Проверки

Из корня репозитория: `python tools/tests/run_all.py` (Python ≥3.10,
`g++`, зависимости `pillow`, `littlefs-python`, `pyserial`, `esptool`).
Проверяются 23 теста сборки/карты/звука, 22 теста инструментов, два
скрипта интерфейсных контрактов и пять хост-программ C++. Линтер
`ruff check --select E4,E7,E9,F tools/tests tools/build fw bin/make_logo.py docs/power-divider.py`
и `git diff --check` прошли.

**Не выполнено:** `pio run -e elecrow-adv-35-horizon` остановился на загрузке
`espressif32@6.9.0` с `HTTPClientError` (реестр PlatformIO недоступен в
этом окружении). Основная сборка single-MCU и запуск на CrowPanel также
не проверены. Хост-тесты не заменяют ни одну из этих проверок; готового
ZIP/EXE эта ревизия не создаёт.

## Оставшиеся риски / следующие шаги

1. `HorizonConfig::save`, `HzMapStore::saveCsv` и `HorizonStore::rewriteMessages`
   пишут прямо в файл через режим `"w"`. Прерывание питания во время записи
   может оставить неполный файл. Менять это только вместе с тестом
   восстановления и миграции; не стирать данные и не менять политику чатов
   «вслепую». Статистика батареи уже использует временный файл и `rename`.
2. Приём/перерисовка карты и запись журналов требуют измерения на железе:
   хост-тесты не определяют задержки UI, ресурс флеш-памяти и влияние на
   радиосвязь. Объём некоторых CSV при чтении не ограничивается отдельным
   общим лимитом строк; перед введением лимита надо решить, как сохранять
   пользовательские точки при старых/неожиданных файлах.
3. Проверить сборку обоих вариантов, первый старт и обновление **без записи
   раздела данных**, все три рингтона и разницу уровней громкости на
   CrowPanel. Windows-упаковку и автономный EXE проверить на Windows.

Посторонний неотслеживаемый `docs/PERFORMANCE_AUDIT.md` оставлен без
изменений и без добавления в коммит.
